# 6. ระบบบริหารจัดการปั๊มน้ำมันบนคลาวด์ (SaaS) — MVP

สร้างตาม **แผนพัฒนาระบบบริหารจัดการปั๊มน้ำมัน (SaaS)** (25 พ.ย. 2569) เฟส 1 · MVP ครบ 4 โมดูล

| โมดูล | สิ่งที่ทำได้ |
|---|---|
| **ปิดกะหน้าลาน** | จดเลขมิเตอร์ต้นกะ/ปลายกะทุกหัวจ่ายพร้อมรูปถ่าย · ระบบเติมต้นกะจากปลายกะก่อนหน้า · คำนวณลิตรและยอดเงินที่ควรได้ · หักน้ำมันทดสอบที่เทกลับถัง · กระทบยอดเงินสด QR บัตร คูปอง เงินเชื่อ · เงินขาด/เกิน**รายคน** · ผู้จัดการตรวจและยืนยันกะ |
| **สต็อกน้ำมันในถัง** | วัดถังทุกวันแล้วแปลงระดับ (มม.) เป็นลิตรด้วยตารางของแต่ละถัง (หักน้ำก้นถัง) · รับน้ำมันจากรถส่ง (เทียบลิตรตามใบส่งกับที่วัดได้จริง) · เทียบยอดตามบัญชีกับยอดวัดจริงรายวัน · เตือนเมื่อถึงจุดสั่ง |
| **Dashboard เจ้าของ** | ยอดขายรายวัน · ลิตรตามชนิดน้ำมัน · เงินขาดเกินรายกะ/รายพนักงาน · สต็อกคงเหลือ · เรื่องที่ต้องดูตอนนี้ · **แจ้งเตือนผ่าน LINE OA** (เงินขาดเกินเกณฑ์ น้ำมันขาดเกินเกณฑ์ ถึงจุดสั่ง สรุปประจำวัน) |
| **ตั้งค่าสาขาและผู้ใช้** | สาขา ถัง ตารางแปลง หัวจ่าย ชนิดน้ำมัน ราคา (มีประวัติ ตั้งล่วงหน้าได้) · สิทธิ์ของพนักงาน ผู้จัดการ เจ้าของ · ประวัติการแก้ไขตั้งค่า |

MVP **ไม่เชื่อมตู้จ่าย** ตามแผน — พนักงานกรอกเลขมิเตอร์และถ่ายรูปแทน จึงใช้ได้ทุกปั๊มทันทีโดยไม่ต้องติดตั้งอุปกรณ์
(ระบบ POS ควบคุมตู้จ่ายเดิมใน `apps/server` + `packages/pump-core` คือฐานของ "ตัวเชื่อมตู้จ่าย" ในเฟส 3)

## สถาปัตยกรรม

```
 ที่ปั๊ม                                   เจ้าของและผู้จัดการ
┌──────────────────────────────┐        ┌──────────────────────────────┐
│ แอปพนักงาน (Flutter)          │        │ Dashboard (Flutter เว็บ/คอม)  │   LINE OA
│ apps/station_app             │        │ แอปเดียวกัน ปรับตามขนาดจอ      │   แจ้งเตือน
│ บันทึกลงเครื่องก่อน แล้วซิงก์   │        └──────────────┬───────────────┘      ▲
└──────────────┬───────────────┘                       │                      │
               │ HTTPS  /api/v1 (token ระบุลูกค้า)       │                      │
┌──────────────┴────────────────────────────────────────┴──────────────────────┴──┐
│ คลาวด์ · apps/cloud-api (Node.js · NestJS บน Fastify)                              │
│  auth · settings · shifts · stock · dashboard · photos · LINE (outbox + worker)   │
│  ทุกคำขอเปิด transaction แล้วตั้ง app.tenant_id จาก session                         │
└──────────────┬────────────────────────────────────────────────────────────────────┘

│ PostgreSQL 16 + Row-Level Security       │   │ ไฟล์รูป (ดิสก์ → S3 ในอนาคต)    │
│ แยกข้อมูลลูกค้าในระดับฐานข้อมูล            │   │ แยกโฟลเดอร์ตามลูกค้า            │
```

ปั๊มนำร่องของเราเป็น**ลูกค้ารายหนึ่ง**ในระบบเหมือนรายอื่นทุกประการ — ไม่มีฟีเจอร์พิเศษเฉพาะปั๊มตัวเอง

## กติกาที่วางตั้งแต่วันแรก — บังคับที่ไหน

| กติกาในแผน | บังคับอย่างไร |
|---|---|
| เงินเป็นสตางค์ (จำนวนเต็ม) ลิตรทศนิยม 3 ตำแหน่ง | ฐานข้อมูล `BIGINT` สตางค์ / `NUMERIC(14,3)` ลิตร · API รับ-ส่งลิตรเป็นสตริง `"1234.567"` · คำนวณภายในเป็นจำนวนเต็มมิลลิลิตรทั้งเซิร์ฟเวอร์และแอป (ไม่มี float) · ยอดเงิน = ลิตร × ราคา ปัดครึ่งขึ้นเป็นสตางค์ สูตรเดียวกันทั้ง SQL, TypeScript, Dart (มีชุดทดสอบตัวเลขชุดเดียวกัน) |
| ห้ามลบหรือแก้ตัวเลขทับ ให้บันทึกเป็นรายการแก้ไขที่มีชื่อคนแก้และเวลา | ตารางเลขมิเตอร์ เงินส่ง วัดถัง รับน้ำมัน ราคา เป็นแบบ**เพิ่มอย่างเดียว**: บทบาท `fuel_app` ไม่มีสิทธิ์ UPDATE/DELETE + trigger กันแก้ทับแม้เจ้าของตาราง · การแก้ = แถวใหม่ที่ชี้ `supersedes_id` ไปแถวเดิม ต้องมีเหตุผล (CHECK constraint) พร้อม `recorded_by` / `recorded_at` · ตารางตั้งค่ามี `audit_log` ผ่าน trigger |
| มิเตอร์ปลายกะ ≥ ต้นกะ และต้องตรงกับต้นกะถัดไป (ยกเว้นมิเตอร์วนรอบ) ไม่ตรงให้เตือนทันที | ตรวจทั้งในแอป (ออฟไลน์ก็เตือน) และที่เซิร์ฟเวอร์: `CLOSE_LT_OPEN` (ข้อผิดพลาด ปิดกะไม่ได้), `OPEN_MISMATCH_PREV` / `CLOSE_MISMATCH_NEXT` (คำเตือน ผู้จัดการต้องกดรับทราบ), วนรอบต้องติ๊กยืนยันและใช้ค่า `meter_modulus` ของหัวจ่าย |
| ทุกตารางมี tenant_id + ชุดทดสอบยืนยันว่าลูกค้ารายหนึ่งมองไม่เห็นข้อมูลอีกราย | RLS ทุกตาราง · FK แบบ `(tenant_id, id)` กันอ้างข้ามลูกค้า · view เป็น `security_invoker` · `test/tenant-isolation.test.ts` ตรวจ: ทุกตารางมี tenant_id และเปิด RLS, ทุกตารางลูกค้า B นับแถวของ A ได้ 0, ไม่ตั้ง tenant เห็น 0, เขียนข้าม/อ้างข้ามไม่ได้, API ทุกเส้นทางตอบ 403/404 |

กติกาเพิ่มเติมจากหัวข้อความเสี่ยงในแผน:

- **ตัวเลขผิดจนเจ้าของเลิกเชื่อ** → ผู้จัดการต้องยืนยันกะ ถ้ามีคำเตือนต้องกดรับทราบและเขียนหมายเหตุ · กะที่ยืนยันแล้วแก้ไม่ได้ ต้อง "เปิดกะกลับ" พร้อมเหตุผล (เก็บใน `shift_events`)
- **เน็ตหลุด** → แอปบันทึกลงเครื่องก่อนเสมอ (คิว outbox ใน SQLite) แล้วส่งทีละรายการ · ทุกรายการมี UUID สร้างในเครื่อง ส่งซ้ำได้ไม่เกิดรายการซ้ำ · สองเครื่องกรอกช่องเดียวกันตอนออฟไลน์ → ต่อเป็นรายการแก้ไข ไม่มีข้อมูลหาย
- **พนักงานไม่ยอมกรอก** → มือถือทำทีละหัวจ่าย ปุ่มใหญ่ ปุ่ม "ใช้ค่าปลายกะก่อนหน้า" กดครั้งเดียวได้ต้นกะ · ถ่ายรูปมิเตอร์แทนการพิมพ์ยาว
- **ราคาเปลี่ยนระหว่างกะ** → ราคาถูกตรึงตอนเปิดกะ ถ้ามีประกาศราคาใหม่ระหว่างกะระบบเตือน `PRICE_CHANGED`

## ใช้งานบนเครื่องตัวเอง

ต้องมี Node.js 22, PostgreSQL 16 และ Flutter 3.50

```bash
# 1) ฐานข้อมูล (ครั้งเดียว — ด้วย superuser)
psql -U postgres -f apps/cloud-api/scripts/db-init.sql

# 2) API
npm install
npm run build:cloud
npm run migrate  -w @fuel-pos/cloud-api     # ใช้ MIGRATION_DATABASE_URL (บทบาท fuel_owner)
npm run seed:demo -w @fuel-pos/cloud-api    # ปั๊มเดโม 14 วัน (รหัสปั๊ม demo)
npm start -w @fuel-pos/cloud-api            # http://localhost:8080/api/v1

# 3) แอป
cd apps/station_app
flutter run -d chrome --dart-define=API_URL=http://localhost:8080/api/v1
```

ผู้ใช้เดโม (รหัสผ่าน `1234`): `owner` เจ้าของ · `manager` ผู้จัดการ · `somchai`, `somsri` พนักงานหน้าลาน

เปิดลูกค้ารายใหม่ (ก่อนมีหน้าสมัครเองในเฟส 2):

```bash
npm run tenant:create -w @fuel-pos/cloud-api -- \
  --slug banna --name "ปั๊มบ้านนา" --owner owner --owner-name "คุณวีระ" --password 'รหัสผ่านยาว ๆ'
```

### LINE OA

ใช้ LINE OA ของระบบ **บัญชีเดียวสำหรับทุกลูกค้า** — ลูกค้าไม่ต้องสร้าง OA เอง

1. สร้าง Messaging API channel แล้วตั้ง `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET`
2. ตั้ง Webhook URL เป็น `https://<โดเมน>/api/v1/line/webhook`
3. เจ้าของ/ผู้จัดการเพิ่มเพื่อน OA (หรือเชิญเข้ากลุ่ม LINE ของปั๊ม) → ในแอปกด **ตั้งค่า → แจ้งเตือนทาง LINE → สร้างรหัสเชื่อม** → พิมพ์รหัส 6 หลักในแชต

ข้อความแจ้งเตือนเขียนลง `notifications` ใน transaction เดียวกับเหตุการณ์ (outbox) แล้ว worker ส่ง — ถ้า LINE ล่ม ข้อความยังรอส่ง

## API โดยย่อ (`/api/v1`)

ทุกเส้นทาง (ยกเว้น login, health, LINE webhook) ต้องมี `Authorization: Bearer <token>` · ข้อผิดพลาดอยู่ในรูป `{ "error": { "code", "message", "details" } }` ข้อความเป็นภาษาไทยแสดงผู้ใช้ได้เลย

| กลุ่ม | เส้นทาง |
|---|---|
| เข้าสู่ระบบ | `POST /auth/login` · `POST /auth/logout` · `GET /auth/me` |
| ตั้งค่า | `GET/POST/PATCH /branches` · `GET /branches/:id/setup` (ชุดข้อมูลสำหรับออฟไลน์) · `/fuel-types` · `GET/POST /branches/:id/prices` · `/branches/:id/tanks` · `PATCH /tanks/:id` · `GET/PUT /tanks/:id/calibration` · `/branches/:id/nozzles` · `PATCH /nozzles/:id` · `/users` · `GET/PATCH /settings` · `GET /audit-log` |
| ปิดกะ | `GET/POST /branches/:id/shifts` · `GET /shifts/:id` · `POST /shifts/:id/readings` · `POST /shifts/:id/pump-tests` · `POST /shifts/:id/collections` · `PUT /shifts/:id/nozzles/:nozzleId/attendant` · `POST /shifts/:id/submit` · `/approve` · `/reopen` |
| สต็อก | `GET /branches/:id/tank-status` · `GET/POST /tanks/:id/dips` · `GET /branches/:id/deliveries` · `POST /deliveries` · `GET /branches/:id/tank-reconciliation` |
| Dashboard | `GET /dashboard?from&to&branchId` |
| รูป | `PUT /photos/:id` (body = ไบต์รูป) · `GET /photos/:id` |
| LINE | `POST /line/link-codes` · `GET /line/recipients` · `PATCH /line/recipients/:id` · `POST /line/test` · `GET /line/notifications` · `POST /line/webhook` |

รายการที่สร้างข้อมูลทุกรายการรับ `id` (UUID) จากเครื่อง — **ส่งซ้ำได้** ตัวเชื่อมตู้จ่ายในเฟส 3 ส่งเลขมิเตอร์เข้า `POST /shifts/:id/readings` ชุดเดียวกันได้เลย ไม่ต้องรื้อระบบเดิม
