## หลักการออกแบบที่สำคัญ

### 1. โปรโตคอลอยู่ในข้อมูล ไม่ได้อยู่ในโค้ด

ตู้จ่ายจีนไม่มีสเปกสาธารณะ และแต่ละรุ่นใช้รูปแบบเฟรมต่างกัน
ระบบจึงอ่านคำอธิบายโปรโตคอลจากไฟล์ JSON แทนการเขียนโค้ดต่อรุ่น

**ผลที่ได้:** เมื่อถอดรหัสโปรโตคอลของตู้จริงได้ ผู้ใช้แก้ไฟล์ JSON แล้วรีสตาร์ต
ไม่ต้องแก้และคอมไพล์โปรแกรมใหม่ และเปลี่ยนยี่ห้อตู้ในอนาคตก็ทำได้เช่นกัน

### 2. ตัวเลขเงินและปริมาตรเป็นจำนวนเต็มเสมอ

- เงิน → **สตางค์** (39.75 บาท = `3975`)
- ปริมาตร → **มิลลิลิตร** (12.34 ลิตร = `12340`)

เพราะ `0.1 + 0.2 !== 0.3` ในเลขทศนิยมลอยตัว การสะสมเศษในยอดขายทั้งวัน
จะทำให้ยอดไม่ตรงกับเงินในลิ้นชักจริง

### 3. บันทึกรายการทันทีที่น้ำมันออกจากถัง

`PumpManager` จะยิง event `transaction` ทันทีที่ตู้แจ้งว่าจ่ายจบ
และ `PumpService` สร้างรายการ **รอชำระเงิน** ในฐานข้อมูลทันที
โดยไม่รอให้พนักงานกดอะไร

เหตุผล: น้ำมันออกจากถังไปแล้วจริง ๆ ถ้าไม่บันทึกตรงนี้
ยอดมิเตอร์กับยอดขายในระบบจะไม่ตรงกัน และตรวจสอบย้อนหลังไม่ได้

### 4. ล็อกหัวจ่ายไว้จนกว่าจะเก็บเงิน

หัวจ่ายที่มีรายการค้างชำระจะสั่งจ่ายรายการใหม่ไม่ได้
กันไม่ให้ลูกค้ารายถัดไปเติมทับรายการที่ยังไม่ได้เก็บเงิน

ปลดล็อกได้ทางเดียวคือรับชำระเงิน (หรือผู้จัดการยกเลิกรายการพร้อมระบุเหตุผล)

### 5. เก็บเงินก่อน แล้วค่อยปลดล็อกตู้

ถ้าปลดล็อกก่อนแล้วบันทึกเงินพลาด จะได้ตู้ที่ว่างแต่ไม่มีรายการเก็บเงิน
เมื่อเก็บเงินสำเร็จแต่ปลดล็อกตู้ไม่สำเร็จ ระบบจะแจ้งเตือนบนหน้าจอ
ให้พนักงานไปกด `Reset` ที่หน้าตู้ — เงินยังถูกบันทึกครบ

### 6. กระทบยอดด้วยมิเตอร์ ไม่ใช่แค่ยอดขาย

ทุกรายการเก็บค่ามิเตอร์สะสม **ก่อนและหลัง** การจ่าย
และการเปิด/ปิดกะจะบันทึกมิเตอร์ของทุกหัวจ่ายไว้

ทำให้ตอบคำถามได้ว่า "มิเตอร์เดินไป 500 ลิตร แต่ระบบบันทึกขาย 480 ลิตร
— 20 ลิตรที่หายไปเกิดจากอะไร"

### 7. โหมดจำลองใช้เส้นทางเดียวกับของจริง

`SimulatedDevice` ไม่ได้ลัดผ่านชั้นใดเลย — มันเข้ารหัส/ถอดรหัสเฟรมจริง
ผ่าน framing, checksum และ byte-stuffing ชุดเดียวกับที่ใช้กับตู้จริง
ต่างกันแค่ชั้น transport ที่เป็นหน่วยความจำแทนสาย RS-485

**ผลที่ได้:** สาธิตงาน ฝึกพนักงาน และทดสอบโปรไฟล์ที่เพิ่งเขียน ทำได้โดยไม่ต้องมีตู้
และ integration test รันบน CI ได้

## การทดสอบ

```bash
npm test
```

ครอบคลุม:

- **codec** — เข้ารหัส/ถอดรหัส BCD, binary, ASCII, checksum ทุกสูตร
  (เทียบกับค่าอ้างอิงมาตรฐานของ CRC-16/MODBUS และ CCITT-FALSE)
- **framing** — เฟรมมาไม่ครบ, สองเฟรมติดกัน, ข้อมูลขยะนำหน้า, byte-stuffing
- **integration** — ไดรเวอร์จริงคุยกับตู้จำลองผ่านโปรโตคอลครบทุกชั้น:
  สั่งจ่ายตามยอดเงิน, ตู้หยุดเองเมื่อครบ, มิเตอร์เดินตรง, ล็อก/ปลดล็อกหัวจ่าย
- **PumpManager** — ยิง event รายการจบเพียงครั้งเดียว, ไม่ให้สั่งจ่ายซ้ำเมื่อค้างชำระ

ฟิสิกส์ของตู้จำลองใช้นาฬิกาจำลองภายใน (ไม่ผูกกับ `Date.now()`)
เทสต์จึงให้ผลเหมือนเดิมทุกครั้ง ไม่ขึ้นกับความเร็วเครื่อง
